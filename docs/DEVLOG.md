## 1. 项目沿革

项目最初是 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)（MIT）的一个分支，
目标很窄：把 QQ 消息转发给 DSH agent，再把回复发回去。

随后逐步演变成「**让 agent 真的住进群里**」：

- 从「只会转发」到「看得懂图、会找图发图、能潜水能接话」
- 从「被动回复」到「自主决定看什么、说什么、什么时候沉默」
- 从「一个 bridge.js」到「消息管线 + 控制台 + 可插拔能力模块」

截至 2026-10-25 的规模：

| 指标 | 数值 |
| --- | ---: |
| 源码文件 / 行数 | 97 个 / 43,718 行（仅 `.js` / `.mjs`） |
| `bridge.js` 行数 | 8,820（重构前为 10,042） |
| 测试脚本 | 128 个 |
| MCP 工具 | 65 个 |
| 控制台路由 | 151 条 |

早期（2026-10-12）相对上游的对比记录在 [feature-comparison.md](feature-comparison.md)：
源码 11,078 → 20,900 行、模块 13 → 38 个、MCP 工具 41 → 50 个。

## 2. 时间线

### 2026-10-20 · 把「能用」补成「像个群友」

- **自动 @**：回复时按概率点名发消息的人，目标优先级为「引用对象 > 未读里按内容匹配的人 > 最近发言者」
- **角色卡注入唤醒提示**：根治「几乎不发表情包」——此前 99.7% 的回合模型根本没看过角色卡
- **称呼不较真 + 角色卡不再被静默截断**：硬切 6000 字会让「禁写外貌」整节丢失
- **加好友 / 入群请求**：私聊管理员并等待裁决，超时自动拒绝，队列落盘
- **GitHub 仓库首页截图**：整页约 15,400px，必须分段发，否则在 QQ 里被压成细线
- **自拍形象图**：看图与发送合并成一个动作，避免「看了图却忘了发」
- **控制台**：新增凭据与连接配置（18）、工具开关（07）、取图额度（12c）卡片
- **发图限额**：每小时 30 → 60，同一张图 10 分钟内不重复发

### 2026-10-21 · 语音、B 站与用量

- **语音合成**：接入 GPT-SoVITS，按概率把回复转成语音消息（可插拔，不装不影响桥接）
- **B 站「视觉 + 听觉」**：抽帧看画面 + 登录态取 AI 字幕，解决「只能看场景、不知道在讲什么」
- **Token 用量**：从记录、每日更新到控制台展示与报表图，支持按日审阅
- **pixiv 凭据配置**；修复「图片查询经常查不到」
- **B 站推荐优先发给活跃群**（按 24 小时群友发言数加权，而非取最冷清的群）
- **连续第三、四次修「@ 错人」**：拍一拍不能当「在叫它」、旧 @ 有保质期、内容匹配失败不能退回「最近说话的人」
- 控制台：可展开元素补动画、排版与卡片编号重排

### 2026-10-22 · 控制台改版与记忆起步

- **控制台大改版**：摘要卡网格 + 液态玻璃 + 卡片弹窗，白名单/管理员改下拉菜单，编号与留白整体重排
- **上下文持久化 Phase 0/1**：情节记忆 + 压缩摘要 + 记忆包
- **语音细节**：停顿更自然、音量修复、音色归档改预设并按语气选参考音频、TTS 权重真正生效、加「选择…」按钮、参数可编辑、试听可播
- **表情包**：从「几乎不用」改为桥接掷骰 + 按语气选候选；管理员可删除收藏表情
- 逐条修：`/yes` 裁决被 QQ 自动同意、mark_read 把新 @ 当已读、拍一拍总戳同一个人、图太大看不到、问 token 用量给不出图、引用合并转发看不懂
- **四修「@ 错人」**：多个「在叫它」的候选时不能只取最新

### 2026-10-23 · 记忆系统与仿真参数

- **上下文持久化 Phase 2**：全量消息日志 + 长期记忆；Phase 3 P0 增加检索式记忆与记忆治理、巡检修复
- **二代仿真（reserved2）** 控制台参数与界面重构
- **非白名单群 @ 机器人**：直接回预设话术，不调用 DSH、不耗 token
- **人格卡可直接在控制台编辑**；收藏表情超过 4MB 上传前自动压缩
- 控制台：02 会话映射显示名称、02b 消息列表撑满、10 白名单悬停摘要、24 刷新反馈、04 实时消息状态流
- 修复：长等待卡死与繁忙 @ 丢失、语音上下文标记与入站转写、桌面停止脚本认不出桥接、@ 不回与搜图请求被吞

## 3. 架构演进

| 阶段 | 形态 |
| --- | --- |
| 初期 | 单个 `bridge.js`，控制台路由、管理命令、消息处理全部内联 |
| 能力扩张期 | 抽出 `mcp-*`、`image-*`、`tts`、`bili` 等能力模块；`bridge.js` 涨到 10,042 行 |
| 重构（2026-10-24 ~ 25） | 控制台 → `console-server.js`；管理命令 → `admin-commands.js`；消息处理 → `src/pipeline/*`；`bridge.js` 只保留编排与状态 |
| 现状 | 97 个源码文件、128 个测试；`bridge.js` 8,820 行 |

重构的三条原则（来自验收记录）：

1. **行为不变**：每一步都以「测试数量与断言数不下降」为门槛
2. **依赖显式**：可变状态通过 `deps.live` / getter 注入，不做隐式全局
3. **结构可测**：跨模块接线约束集中到 `test-bridge-wiring.mjs`，不靠拼接源码规避统计

## 5. 工程实践

- **测试优先于口头保证**：128 个脚本、数千条断言；「必须拦截」与「必须放行」两类断言都要写。
  需要真实服务的脚本由汇总器标注为「环境不满足」，避免把环境问题误判成代码回归。
- **失败要显式**：读不到就如实说读不到，不让模型猜。验证页、空正文、取图失败都有
  `ok:false` 与可读原因。
- **报错不进群**：所有异常走管理员私聊通道，群友看不到内部机制。
- **可移植**：脚本按自身位置或环境变量解析路径；模型权重、音频与本地状态一律不入库。
- **文档分层**：README 只做概览，功能细节进 FEATURES，配置与运维进 CONFIGURATION，
  设计约束进 DESIGN，流水账进 CHANGELOG，本文件按时间讲「为什么」。
- **发布前脱敏**：真实账号/群号/昵称替换为占位符，夹具改为合成数据，
  真实 API key 不入库；发布副本与工作副本分离，避免误改生产目录。

## 6. 已知限制与后续

- `test-console` 需要本机有一个**运行中的桥接**（`127.0.0.1:3100`），否则只能验证到连接失败
- 部分测试依赖真实图站 / 网关 / SnowLuma，离线环境会被标记为「环境不满足」
- DSH 的 prompt 协议只接受 `text` / `image`，因此视频与音频只能转成「抽帧 + 字幕」
- 模型权重（CLIP、GPT-SoVITS）与 Upscayl 二进制不入库，需自行下载
- Windows 优先：ffmpeg 渲染、路径处理与启停脚本按 Windows 编写
- 上下文记忆仍在迭代：Phase 3 的灰度与 24 小时观测尚未完成

## 2026-10-26 ~ 10-27：重构二期（R2 ~ R4）与工程基线

这轮把 0.4.0 之后积累的结构债一次清掉：

- **状态层**：22 个 JSON 状态文件统一到 `src/state/store.js`（原子写、版本迁移、mtime 热重载）。
- **插件化**：新增插件宿主与运行时，TTS 作为第一个整体出核的可选功能；控制台拿到 `/api/plugins` 与插件卡片插槽（`ctx.console.registerCard / registerRoute`）。
- **bridge 拆分**：会话、社交调度、任务、加入请求、Token、图库、表情库、媒体、入站派发、引用解析、报错通道等 16+ 个模块出核，`bridge.js` 8,621 → 6,475 行。
- **控制台分域**：154 条路由按域拆进 `src/console/routes/*`，由 `src/console/router.js` 统一分派；`console-server.js` 7,191 → 601 行。迁移过程中顺手修掉两处老隐患（catch 引用 try 内变量、注册期快照 `sendJson`）。
- **工程基线**：复杂度以 R4 后状态重估为新基线（`docs/COMPLEXITY.md`，综合「中」）；版本号标准落地（`docs/VERSIONING.md`，`npm run version:set` + 护栏测试），本仓库版本进入 0.4.1；上游（Derpyu520/qq-bridge，MIT）的版权与许可声明整理进 `THIRD_PARTY_NOTICES.md` §0。
