> 依赖袋口径都变了，不要拿本文件的数字和现状直接对比。


> 评估对象：0.4.0 的发布树（不含 `node_modules` / `state/` / 模型文件）。
> 指标为静态统计，采集命令见文末；数值随代码变化，结论看趋势而非绝对值。

---

## 1. 结论

**综合复杂度：中高（偏上）。**

项目已超出个人业余工具的规模，接近一个中小型后端服务：单人仍可维护，
但前提是测试与文档持续兜底。真正的复杂度不在代码量，而在
**长驻进程 × 多会话 × 多定时器 × 外部不稳定服务**构成的状态空间。

| 维度 | 评级 | 判断依据 |
| --- | --- | --- |
| 代码规模 | **高** | 43,815 行 / 97 个源文件 |
| 结构耦合 | **中高** | 无循环依赖，但存在两个巨型模块与 265 项依赖袋 |
| 运行时状态 | **高** | 22 个状态文件、77 个定时器、多会话并发 |
| 外部集成 | **高** | 13 类外部服务/工具，任何上游变化都会变成 bug |
| 配置复杂度 | **高** | 447 个配置键、56 个工具开关 |
| 测试保障 | **中高** | 129 个脚本 / 约 4,600 条断言，但 9 个依赖真实服务 |
| 文档 | **高** | 12 份 / 3,657 行，分层清晰 |

## 3. 五维分析

### 3.1 规模：长尾健康，头部过重

97 个模块的平均行数是 452，说明大部分模块职责清晰。
但 `bridge.js` 与 `console-server.js` 已经接近"不可整体理解"的体量——
改动其中一处需要通读上下文，代码评审和测试定位都变慢。

### 3.2 结构：拆分完成，耦合未解

- `bridge.js` **扇出 71**：依赖几乎全部模块，仍是事实上的上帝对象
- 传给 `createConsoleServer` 的依赖袋有 **265 个顶层条目**
- 无循环依赖，模块边界总体单向

结论：**代码位置分开了，控制关系没分开。**
重构把函数搬进了 `src/pipeline/`，但可变状态、定时器与跨模块编排仍集中在 bridge。

### 3.3 行为：复杂度集中在运行时

| 控制流代理 | 数量 |
| --- | ---: |
| `if` | 4,274 |
| `try` | 678 |
| `await` | 803 |
| 定时器 | 77 |

历史上反复出现的「@ 不回」「长等待卡死」「繁忙时丢消息」「@ 错人」，
都不是单函数写错，而是**时序与状态竞争**。这是项目最难的 20%，
也是单元测试最难覆盖的部分。

### 3.4 集成：外部面很宽

13 类外部依赖：DSH、OneBot/SnowLuma、safebooru、pixiv、yande.re、SauceNAO、
4 个搜索引擎、X、GitHub、微信公众号、GPT-SoVITS、ASR、Upscayl、Chrome/Edge、ffmpeg。

任何一方的风控、协议或接口变化都会直接表现为项目 bug；
9 个测试脚本需要真实服务，无法在离线环境全量验证。

### 3.5 配置：447 个键的组合爆炸

配置默认值分散在三个位置：`config.example.json`、`src/bridge.js` 的 `loadConfig()`、
以及各模块自己的兜底逻辑。模板缺一个字段就会静默吃默认值——
`images.enabled` 缺失曾导致克隆者完全发不出图。

---

## 4. 风险排序

1. **`bridge.js` 的状态中心化**：8.8k 行、扇出 71，是所有改动的必经之路
2. **`console-server.js` 的依赖袋**：7k 行、265 项平铺依赖，接口难收敛
3. **22 个状态文件的并发写入**：已有原子写，但跨文件一致性没有统一事务
4. **配置面 447 键**：无 schema 校验，默认值三处漂移
5. **外部集成缺少契约测试**：上游变化只能靠线上报错发现

---

## 5. 判断与建议

**一句话：一个人能维护，但已经到"必须靠测试与文档撑着"的上限区间。**

继续加功能前，优先做两件收益最高的事：

1. **配置 schema 化**（低风险、立刻见效）：用已有依赖 `zod` 定义配置，
   启动即校验、由 schema 生成模板，消灭"模板缺段"类问题
2. **拆分 bridge 的状态与编排**：按域抽 store，bridge 只保留 wiring，
   目标降到 5,000 行以内

其余建议（控制台拆路由、统一状态写队列、把读源码的测试改为行为测试）
见桌面上的《重构方案》。

## 8. R4 收尾快照（2026-10-26）

| 指标 | R4 后 |
| --- | ---: |
| 源码文件 / 行数 | 138 / 46,975 |
| `bridge.js` | 6,475 |
| `console-server.js` | **600** |
| 最大路由模块 | 802（`console/routes/10-images.js`） |
| 测试脚本 / 行数 | 145 / 24,946 |
| 配置键 | 479 |

| 循环依赖 | 0 |

控制台不再是一个巨型请求处理器：`src/console/router.js` 负责 exact/prefix 匹配，`src/console/routes/*.js` 按域声明 `routes` 清单并保留原来的 if 链，`console-server.js` 只做鉴权 / CSRF / agent 白名单 / 静态页 / 404。控制台依赖袋从 262 项降到 18 项；各域模块从 `deps` 取自己用到的切片（18 个模块合计仍引用大部分依赖，但**单个模块的可见面**已收窄）。

插件控制台插槽：插件可 `ctx.console.registerCard()` 贡献卡片、`registerRoute()` 挂 `/api/plugins/<id>/*`（需 `console:route` 权限）；核心只转发与展示文本元数据，不执行插件脚本。关于页的插件卡片槽位由 `/api/plugins` 的 `console.cards` 驱动。

已知未完成项：依赖袋本身仍是 bridge 侧的平铺对象（R4-4 只完成了"单模块可见面收窄"，未改成 6 个领域对象）；`console.html` 仍是单体文件，插件卡片目前只在关于页渲染，尚未做成摘要卡网格里的独立卡片。
