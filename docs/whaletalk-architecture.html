01

消息主链路

QQ 消息进入 Bridge，由 DSH 完成回合，再经发送队列回到 QQ。

LIVE PATH
01 / INPUT QQ 群聊 / 私聊 文字 · 图片 · 引用 · 转发 · 拍一拍
02 / GATEWAY SnowLuma OneBot v11 · HTTP 3000 · WS 3001
03 / INGRESS Bridge 入站 准入 → 解析 → 管理命令 / 挂起 / 静默分流
04 / SCHEDULE 会话与唤醒 session-service · social-service · wake
05 / AGENT DSH / 模型 prompt · tool calls · usage · turn
06 / EVENTS 事件泵 dsh-events · turn-metrics · 自动收尾
07 / OUTPUT QQ 回归 send-queue → qq-send → OneBot

主链路之外的旁路：控制台（3100）与 MCP 工具调用最终也落到同一套 Bridge 服务和状态层； 所有发送按会话进入 send-queue，不恢复全局发送链。

02

控制台用例层

控制台请求不经过 QQ 主链路，直接进入服务与状态层。

PORT 3100
Browser→ console-server→ routes 19→ facets→ read-model 17/ commands 19→ 8 领域服务
入口契约：createConsoleServer 只接收 8 个领域对象， 266 个键各有唯一归属；路由最大解构 3 项，仅鉴权 helper。
兼容残留：flattenConsoleServices() 仍会把领域摊回 266 键， 供 console-server 自身的鉴权 / 静态资源路径使用。新路由不再依赖它，后续可删除。

04

状态与持久化

同一套 JSON store 机制承载会话、记忆、媒体与指标。

STATE

会话与社交

state/sessions.json state/social-v2.json state/session-history.json state/session-gap.json

记忆与检索

state/context/<key>/messages.jsonl state/context/<key>/episodes.jsonl state/shared-memory.json state/bili-memory.json

媒体与缓存

state/image-lib/ state/stickers.json state/token-report/ state/upscale-cache/

指标与运维

state/turn-metrics.json state/token-usage.json state/token-fuse-state.json state/plugins/<id>/

所有 JSON 统一经 state/store.js 的 createJsonStore()： 版本号、原子替换、损坏备份、默认值；数组状态使用 {__version, items:[]}。 跨进程状态使用 reloadOnMtime，避免桥接与 MCP 互相覆盖。

05

插件运行时

第一方插件通过 manifest + 公共 plugin-api 接入，不直接依赖 Bridge 内部。

PLUGINS
images stickers tts upscale bili web-search x-posts media-tools slang shared-memory qq-mode-console content-review
manifest.json→ load()→ start()→ stop() · ctx.capabilities · ctx.state.store · ctx.console.registerConfigItems · ctx.mcp.registerTool

插件只能写 state/plugins/<id>/，发送必须走 ctx.send； 权限边界是声明式审计，不是代码沙箱。Core → plugin/lib 直接导入为 0。
