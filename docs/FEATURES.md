## 基础通信

- QQ 群/私聊消息 → DSH 会话提示词；`chat` / `reserved` 的普通回复自动转发，`reserved2` 通过发送工具发言
- 每个 QQ 会话映射到独立 DSH 会话，归组到「QQ 聊天」工作区，映射持久化在 `state/sessions.json`
- agent 用 `ask_user_question` 提问 → 转发到 QQ，群友回复即自动应答
- agent 请求工具审批 → 转发到对应 QQ 会话，只有管理员回复「通过」/「拒绝」才会提交决策
- 管理命令仅管理员可用：`/reset` / `/new` 由桥接清理会话映射与状态，其他支持的 DSH 斜杠命令（如 `/model`）交给 DSH
- **群白名单可在群里直接管**：`/wl` 查看、`/wl add 群号 [群号...]` 加入、`/wl del 群号 [群号...]` 移出，改完立即写回 `config.json` 并热更新内存，不用重启。管理员在**尚未加入白名单的新群**里也能执行（否则没法把自己加进来）
- DSH 重启期间提示词暂存在内存队列（最多 50 条/会话，满时丢弃最旧项）；二代未读另存本地，桥接重启后可补排唤醒

## 引用与上下文

- 群聊引用解析成「被引用人 + 原文」注入（`[引用 某人：原文]你的话`），让 agent 判断这句话在对谁说，不会把群友之间引用第三方的话误当成指向自己
- **引用里的图片不会丢**：原版只取文字，现在会把图片段一并解析并提示怎么取图
- agent 可以引用回复（`qq_reply` / `replyToMessageId`），支持传 `latest` 符号引用避免猜错编号
- 合并转发消息（聊天记录）可读取，含嵌套转发与内部图片

| 能力 | 说明 |
| --- | --- |
| 看图 | `qq_get_message_images` 把消息里的图直接以图像内容返回（视觉模型可看懂），支持别人发的消息、动图抽帧 |
| 超分放大 | **群友可以主动要**：说「帮我超分 / 放大一下 / 来个高清的」就会做，放大后的图直接发回聊天。也用于模型自己看不清细节时（那种情况不会刷群）。装了就启用，没装时菜单和工具都不出现，不影响其它功能 |
| 图库 | 多源检索 safebooru / pixiv / yande.re，落盘缓存、按标签与日榜挑选 |
| 按需发图 | `qq_send_image` 从已启用的图库取图；当前实现把图片与文字分条发送 |
| 画风打分 | 可选的 CLIP 画风相似度评分，用于图库筛选，依赖相应模型与配置 |
| 差评换图 | 对近期发图的有效差评可触发换图，并从本地图库移除、拒绝再次入库；不代表撤回 QQ 中已发出的图片 |
| 收藏原图 | 尝试回源，将原图存到机器人本机 `collected/`；该工具不把原图文件回传给群友 |
| 反向搜图 | 配置 SauceNAO API key 后尝试查出处；匹配率受图片和图源影响 |
| 指定图源 | 识别「从 pixiv 找」等要求；只使用已启用且可访问的来源，不保证一定有结果 |
| 代理隧道 | CONNECT 隧道绕 DNS 污染取图（pixiv 等） |

## 取图额度（图片插件卡）

图片插件卡实时显示取图链路的三类上限。**它们都会表现成"取不到图"，但原因完全不同**，混在一起排查会走错方向：

| 类型 | 含义 | 用完了会怎样 |
| --- | --- | --- |
| **SauceNAO 反查额度** | 每天 100 次、30 秒内最多 4 次（免费额度） | **当天无法再反查**，明天自动重置。这是唯一「真的会用完」的上游额度 |
**额度的两条修正（2026-10-21）**：

1. **只有真正完成一次搜索才扣额度**。原先的写法是「拿到任何响应就先记账，再按错误文案正则
   决定要不要退回」——实测两个问题：① Cloudflare 挑战页的文案不在那条正则里，于是**被风控挡住
   也照样扣了一格**，群友看到「没搜到」额度却少了；② 靠错误文案判断太脆，上游改一个字就漏。
   现在改成显式判断 `parsed.ok === true` 才记账，风控页 / 非 JSON / 上游报错 / 连接失败都不扣。
2. **「Cloudflare 挑战页」的判定原先会误报**：只测 `/cloudflare/i`，而 SauceNAO 正常首页里
   也有 `Cloudflare Web Analytics` 的脚本注释 → 正常页面被当成挑战页。现在要求
   `Just a moment` / `cf-chl` / `challenge-platform` 等真正的挑战特征，另外补了
   「HTTP 403 且响应不是 JSON」这条兜底判据。

**重启不丢额度（2026-10-23）**：`imageFetchedAt` 与 SauceNAO 当天用量原先只在内存，桥接重启后控制台会回到 100/100 / 可补货，看起来像"额度没更新"。现在分别持久化到 `state/image-fetch-state.json` 和 `state/reverse-search-quota.json`；窗口 hits 加载时按 30 秒过滤，跨天自动清零。

**已知限制**：当前代理出口 IP 被 Cloudflare 标记时，反查会持续返回 403 挑战页——
实测加全套浏览器请求头（Referer / Origin / Sec-Fetch / sec-ch-ua）**也没用**，
只能换代理节点或出口地区。这种情况下报错会明确写「不是 key 或额度问题」，不要反复重试。

| **拉取冷却** | 两次「补货」之间的最小间隔（`images.cooldownMs`，默认 30 分钟） | 冷却中不能手动补货，但仍可用库里已有的图；按标签现拉不受它限制 |
| **图库容量** | `maxFiles`（300 张）/ `maxTotalBytes`（256MB） | 满了会淘汰最久未用的旧图，**不影响继续取图** |

另外还显示：每会话发送限频（`sendCooldownMs` / `maxSendPerHour`）、各图源的启用状态与有无代理。
「某个源没开」常被误当成额度问题，所以单独列出来。

- 反查的「窗口内用量」在 `stats()` 里按**当前时刻**重新计数，不直接用 `hits.length`——后者要等下次请求才清理过期时间戳，会显示一个虚高的数字。
- 同一张图反查有 24 小时缓存（按 sha1 分桶），命中缓存**不消耗额度**，卡片会显示缓存张数。
- 上游拒绝（限流/配额）会退回本地计数，避免"key 配错就把当天 100 次全耗光"。

**不重复发（2026-10-20 用户要求「发过的图在十分钟内不要重复发」）**

同一张图在 **10 分钟**内不会被再次发出，按内容哈希判断（`recentSendBlockMs`，默认 600000）。

这条不是简单的"加个过滤"能解决的——原来的去重线索放错了地方：
`pruneSent` 会在 10 分钟后把发过的条目**整个从 index 删掉**，同一张图再被查询时会重新拉取，
`add()` 生成一条全新的 `useCount: 0` 记录，于是"新鲜度"判断认为它从没发过，又发一次。
实测日志里 `pixiv:150564360` 在 4 分钟内被发了 **3 次**，就是「发 → 删 → 重拉 → 又发」这个循环。

修法：单独记一份 `state/image-lib/recent-sent.json`（**内容哈希 → 发送时间**），
条目删了它还在。挑选时这一层是**硬过滤**：全被挡掉时宁可返回空让上层去现拉新图，也不发重复的。

两个配套细节：
- **dryRun（发图预检）要计入这一层**，否则预检说"本地有图"、实际发不出去。
- **差评换图要跳过这一层**：那张刚被拒的图已经移出图库，剩下能选的本来就不可能是它；
  若还按 10 分钟拦，只有一张图可用的角色会直接报"都发过了"——那是把"防重复"变成了"不许换"。

被挡掉时错误文案要说明"是刚发过、再等等"，**不能报"没找到"**——后者会让模型以为这角色库里没有，
进而换词乱搜，而实际只是要等几分钟。

## Token 用量（控制台 14）

控制台卡片显示**今日 / 累计 / 近 14 天趋势 / 按模型明细**，数据来自 DSH 会话转录的本地解析（不调用任何 API）。

**按日审阅**：卡片里有一个下拉，默认「总计（全时段）」，选中某一天后，下方「按模型」只显示
**那一天的模型调用量**，并给出当天的输入/输出/缓存读/调用合计。下拉列出全部已统计的天
（不只是表格里的最近 14 天），选择会在 60 秒自动刷新之间保留。

这需要日×模型的**联合分布**（`dayModels`）。为什么不从「按天」和「按模型」两张表反推：
两者都是**边际汇总**，某模型跨 3 天共 10M 时无法知道每天各多少。所以解析每条 usage 时
同时按 `(天, 模型)` 分桶。测试里做了三重交叉校验：每天各模型 calls 之和 = 当天 calls、
dayModels 总量 = days 总量、每个模型的全局 calls = 它各天之和。

- **每日更新**：跨天自动重算；平时每 6 小时刷新一次（让"今日"数字不会僵一整天）；
  也可以点「重新统计」手动刷新。结果落盘 `state/token-usage.json`。
- **不在 HTTP 请求里现算**：全量扫一遍要 13~16 秒（15 个文件、最大的 72MB），
  放在 GET 里会卡住控制台。GET 只读缓存；需要重算走 `POST /api/socialV2/token-usage-refresh`
  （后台跑，立刻返回）。
- **增量扫描**：按文件 `mtime + size` 做指纹，没变的文件直接复用上次解析结果。

**按会话统计（2026-10-25）**：16 卡新增「按会话」排行，每个群/私聊同时显示两个口径——
**当前会话**（`state/sessions.json` 里的当前 DSH sessionId）和**累计**（该 QQ 会话名下所有历史
sessionId + 情节摘要器）。轮换（上下文超限 / 模式代际 / reset / 删除）后旧会话的消耗不会从累计里消失。
归属靠 `state/session-history.json`：创建、轮换、重置、删除各记一条，首次启用时从
`state/context/<key>/compactions.jsonl` 回填历史 sessionId；仍无主的会话单列为「内部 / 历史无主」。
情节摘要器直连网关、不经过 DSH，通过 `onUsage` 回调单独记进 `summarizer` 桶，补齐原先的统计盲区。
24 号卡每行新增「今日 Token（累计）」列，可直接和会话体积、episode 数并排看消耗大户。
「按日审阅」下拉对会话表同样生效：选某一天时「当前会话当日 / 累计当日 / 摘要器」都只统计那一天，
选「总计」才看全时段；数字列表头与内容统一右对齐。

**群友也能问**：`qq_token_report` 会把同一份数据渲染成一张 PNG 发到当前会话
（今日/近 7 天/累计 + 每日柱状图 + 按模型占比），并回一段**与图同源**的文字摘要，
供模型在追问时如实回答。卡片里的「生成报表图」按钮可以在控制台直接预览这张图。
渲染走 Chrome 无头截图，按 HTML 内容指纹缓存；数据默认取 6 小时内的统计，
群友问"今天到现在"时模型可传 `fresh=true` 先增量重算（约 7 秒）。

解析逻辑复用 `scripts/token-usage.mjs` 已验证的思路（已抽成 `src/token-usage.js`），两个坑都已踩平：
**会话文件是 zstd 多帧拼接**（一次性解只拿到第一帧，必须按魔数 `28 B5 2F FD` 切帧）；
**同一份 usage 在 `assistant/chunk` 与 `assistant/message` 各出现一次**（必须按
`(turn, step, input, output, cacheRead)` 去重，否则用量翻倍）。

在那里之上修了两个问题：

1. **模型归属**：usage 事件里**没有** model 字段。它在 `request/header` 的
   `data.header.config.model`，而该事件**没有 turn 字段**——只能按时间顺序继承
   （header 出现在其后 usage 之前）。旧脚本按 `data.model` 取，「按模型」只统计到 67 次
   （总数 40006）。现在 40017 次调用全部有模型归属。
2. **扫描范围**：`~/.dsh/sessions` 下还有别的项目和一堆测试工作区
   （`state-probe-*` / `state-tmp-*` / `state-local-*`），全扫会让"今日用量"虚高。
   现在只认名字含本项目且以 `-state-agents--` 结尾的目录（实测从 391 个文件降到 15 个）。

实测规模：累计约 **40,017 次调用 / 8,917 回合**，输入 991.99M、输出 5.48M、缓存读 20.03B。

## 工具开关（控制台 07）

AI 能调用哪些工具由 `socialV2.tools` 逐个控制，**关闭后桥接 API 会直接拒绝调用**。

清单是**单一事实源**（`src/tool-flags.js`），控制台从 `GET /api/socialV2/tool-flags` 读它渲染——
不再把复选框写死在 HTML 里。这一改动直接来自一次查漏：

| 查漏发现 | 数量 |
| --- | --- |
| MCP 实际注册的工具 | **55** |
| 旧控制台里的复选框 | 30（且部分 flag 对不上） |
| **真正生效但完全没有 UI 开关**的 | **10**（archiveImage / imageSource / reactMessage / rejectImage / refreshImageLib / reverseSearch / sendImage / getFeatureMenu / groupFiles / deleteSticker） |
| 无条件注册、也没有任何说明的 | 4（qq_status / qq_list_groups / qq_get_group_members / qq_get_group_history） |

根因是清单写死在控制台 HTML 里：加工具时只改后端（或只改前端）就漂移。
现在清单只在 `tool-flags.js` 定义，`test-tool-flags.mjs` 会断言**清单与 MCP 注册的工具完全一致**——
以后加了工具却忘了登记，测试立刻失败。

视觉上重做成：

- **可搜索**（工具名 + 说明），37+ 个开关不再是一堵墙
- **按功能分组、可折叠**（上下文与状态 / 发送 / 调度与记忆 / 看图与图库 / 表情包 / 内容抓取 / B 站 / 黑话 / 基础查询），
  折叠状态存 localStorage
- **每组有「全开 / 全关」**，顶部有「全部展开 / 全部收起 / 全开 / 全关（危险）」
- **危险项左侧红条 + 「慎关」标记**；不可关闭项灰显 + 锁标记；关闭的项整行变淡
- 顶部统计「已启用 N / 总数，覆盖 M 个工具」

## 插件配置与连接（原控制台 20）

原 20 卡已拆分：图片、B 站、X、联网搜索、媒体工具各有一张「配置 / 连接」卡；核心 SnowLuma / 控制台令牌放在「控制台工具」组。配置项由插件通过 `ctx.console.registerConfigItems()` 注册并实现 `get/set`，核心只提供通用 UI 与 `/api/plugins/<id>/config`。所有卡共用密码样式、右侧眼睛切换明文、每项 `?` 说明、底部保存与重启。

| 归属 | 项目 |
| --- | --- |
| 图片插件 | SauceNAO API Key、pixiv PHPSESSID / device_token、图源代理 |
| B 站插件 | SESSDATA / buvid3 |
| X 插件 | auth_token / ct0、X 抓取代理 |
| 联网搜索插件 | 联网搜索代理 |
| 媒体工具插件 | GitHub 截图代理 |
| 控制台工具 | SnowLuma accessToken、控制台访问令牌 |

**连接类不脱敏**（2026-10-20 用户要求）：代理地址不是秘密——就是个 `http://127.0.0.1:7897`，
藏起来反而让人没法确认填得对不对。所以 `kind: 'text'` 的项**直接显示明文**，也没有眼睛按钮。
只有 `kind: 'secret'`（真正的 key / Cookie）才打码。

**密钥默认不下发明文**——列表接口只回「是否已配置」+ 脱敏预览（`d4••••••••••00`）。
隐藏态下输入框里装的就是这串脱敏值，用 CSS（`-webkit-text-security: disc`）渲染成**黑色圆点**。

- 它是**真正的 `input`**（不是 `div`、不是 `type=password`），所以可以选中、可以 Ctrl+A、可以复制——
  不同浏览器对 `password` 的选区/复制行为并不一致，用普通 input + CSS 才稳定可控。
- 点眼睛才向服务端要明文（`?reveal=1&key=xxx`），再点一次把脱敏串填回去。
  **页面在隐藏态从不持有完整密钥**，截图、DevTools 检查、浏览器扩展都拿不到明文。
- 因此「全选复制」在隐藏态复制到的是脱敏串；要复制明文需先点眼睛。
  这是刻意的取舍：少一次点击，换来页面不长期持有密钥（用户 2026-10-20 确认保持此方案）。
- **待提交的值存在每个配置卡实例自己的内存 Map 里**（`edited`），不是只靠 DOM 上的标记。
  点眼睛 / 保存后都会重建 DOM，重建出来的输入框没有 `edited` 标记——
  只靠 DOM 时，用户在两次重建之间改过的项会凭空消失，表现就是「点一次保存只保存了最早改的那个」。
  现在的规则：编辑即写入 Map；渲染时把未保存的值回填进输入框；
  **只在保存成功后**移除提交成功的项（失败的留着让用户改完再点一次）。
- 隐藏态里的脱敏串**绝不会**被当成新值写盘（否则会把真实密钥覆盖成一串圆点）。

卡片跨两列（约 700px）而不是占满整行：一列 340px 会把输入框压得看不见，整行又拉成一条长线。
凭据项与连接项用**同一种输入框外观**，区别只在多一个眼睛按钮。

**需重启的项标着黄色「需重启」**（B 站 cookie、SnowLuma token、控制台令牌——它们只在启动时加载一次）；
其余标「即时生效」。保存后返回 `applied` 字段告诉前端到底生效没，避免用户以为白填了。
底部「重启桥接」按钮复用既有的 `/api/restart`，会先确认、重启后轮询等待恢复（60 秒上限，带秒数进度）。
该端点**自己拉起新进程**（detached + unref），不依赖外部守护窗口：只做 `process.exit(0)`
等别人重启时，用 nohup / 计划任务启动的场景会直接停服。

说明文档写在 `src/credentials-doc.js` 里（内联到控制台，用弹窗展示），
每项都写了**怎么取、生效方式、安全提醒**，不是只有一句"填这里"。
弹窗带弹出/关闭动画（`transform + opacity` 过渡），支持 Esc 与点遮罩关闭。
关闭按钮的 `×` 用 flex 居中 + `line-height: 0`——早先用固定宽高 + `line-height: 1` 时字形会贴上沿。

保存前有形态校验：代理必须是 `http(s)://`、控制台令牌至少 16 位、密钥过短会被拒——
宁可在保存时挡住，也别存进去后再去排查"为什么连不上"。
写入沿用原位置（`config.json` / `state/*.json`），**不新建集中明文文件**：集中一处只会扩大泄露面。

## 加好友 / 入群请求（控制台 13）

有人加 bot 好友、或把 bot 拉进群时，桥接会**私聊管理员**并等待裁决：

- `/yes 编号` 同意　`/no 编号` 拒绝　`/pending` 查看待处理（也认「同意」「拒绝」这类中文短句）
- 默认 **5 分钟**内有效，超时**自动拒绝**

**默认不自动同意**（`joinRequest.autoApprove: false`）。加好友和入群都在扩张账号暴露面：
好友能私聊它、群能让它出现在陌生人面前。没人处理就拒绝，这是 fail-closed 的选择。

几个刻意的设计：

- **只认管理员私聊里的指令**。群里的「同意」可能是群友说的，而这是账号级权限变更，
  不能靠一句话就放行。
- **多条待决时必须带编号**。同时来两个请求时，光说「/yes」不生效——会提示你用编号指定，
  避免误批。
- **超时要真的提交拒绝**，不能只是从队列里删掉。这里踩过一个坑：队列加载时会把过期项
  静默丢弃，于是 `QQ 侧从未收到拒绝、申请人一直挂着等`，而日志里什么都没有。
  现在启动时会把"重启前就已过期"的请求捞出来补发拒绝（实测日志：
  `启动时发现 1 条已超时的旧请求，已补发拒绝`）。
- **通知不到管理员就自动拒绝**。没配 `ownerQQ` 或私聊发送失败时不能让它干等。
- 队列**落盘**（`state/join-requests.json`），重启不丢；编号重启后继续递增，不重排
  （否则管理员看到的是 2、点的时候变成 1）。
- 控制台「14 加好友 / 入群请求」卡片能看到待决列表与剩余时间。

## GitHub 仓库首页截图

群友发 `github.com` 链接（或说「看看这个仓库」）时，模型调 `qq_github_shot`，
桥接会**把仓库首页整页截图发到群里**——Star 数、文件列表、README 排版、语言占比条，都是渲染后的真实样子。

- **必须分段发**：实测仓库首页整页约 **15400px**。一张 1400×15400 的图在 QQ 里会被等比压成
  灰色细线（文字只剩 1~2 像素高），等于没截。按 2400px 切成 5 张，每张 1400×2400，文字清晰可读。
  发送前会先发一句「整页 N px，分 M 张发」，群友知道后面还有。
- **实现走 CDP，不用 `--screenshot`**：功能菜单那套「`--dump-dom` 量高度 + `--screenshot`」只适用于
  自己生成的静态 HTML（高度预埋在 `data-h` 里）。外部页面量不到高度、固定高度会留白或截断，
  且高度随宽度响应式变化。所以起一个 headless Chrome（`--remote-debugging-port=0`），
  用 `Page.getLayoutMetrics` 拿真实内容尺寸，再用 `captureScreenshot` 的 `clip` 参数按段截
  （**不靠改视口大小**——那会触发响应式重排，导致各段内容错位）。
- **必须走代理**：实测本机直连 `github.com` 会 `ECONNRESET`。代理取
  `socialV2.githubShot.proxy` → 回落到 `socialV2.images.proxy`。直连失败时报错会直接点明要配代理。
- **链接形态**：`https://github.com/owner/repo`、`owner/repo` 简写、带 `www`、`.git` 后缀都认；
  `/issues`、`/tree/main/x`、`/blob/...`、`/releases` 这类子页面**归到仓库首页**
  （需求就是"截首页"）；`/topics`、`/trending`、`/features` 等保留路径直接拒绝，不会变成通用截图器。
- 同一仓库同一会话 **30 秒内不重复截**（群友常连发两次链接，而截图要起 Chrome、约 10~20 秒）。
- 发送前照旧过 agent token / 模式准入 / 总暂停 / 静默四道检查；某张发送失败就停，
  一张都没发出去时明确报错，不让模型以为发了。
- 实测：整页 15422px → 截到 12000px（`maxHeight` 上限）→ 5 张，共约 19.6 秒。

## Token 用量报表图

群友问「用了多少 token / 今天消耗多少 / 这个月烧了多少」，模型调 `qq_token_report`，
桥接把用量统计渲染成一张 1080 宽的 PNG **直接发到会话**（今日/近 7 天/累计 +
每日柱状图 + 按模型占比），并回一段**与图同源**的文字摘要。

- **为什么还要给文字**：只给图的话，群友追问「那昨天呢」「哪个模型用得多」时，
  模型会凭印象编一个数——和刚发出去的图对不上。摘要与图上数字由同一个 report 对象出，
  模型照抄即可，不需要自己算。
- **口径**写在图里：输入 token 是**每次请求累加**（同一段上下文每轮都重发），
  缓存读单独统计；不出现任何金额（没有单价数据）。
- **空白日补 0**：近 7 天按日历补齐，没说话的那天画灰色底线，不会把相隔 6 天的两根柱子画成相邻。
- **模型不合并**：`global:` 与 `cn:` 同名模型显示成 `deepseek-v4.1-flash（global）` / `（cn）`，
  它们是两个不同的池。
- 缓存命中率 = `cacheRead / (input + cacheRead)`；只拿 input 当分母会算出 >100%。
- 数据默认取 6 小时内的统计；`fresh=1` 先增量重算（约 7 秒）。图上标「更新于 X 前」，过期显示黄标。
- 渲染走 Chrome 无头截图（先 `--dump-dom` 量高再截，与功能菜单同一套），
  按 HTML 内容指纹缓存、并发合并、旧图清理。

## B 站：视觉 + 听觉

模型只能收 **文字和图片**（网关实测只接受 `text` / `image_url`；音频、视频内容类型全被拒；
DSH 的 prompt 协议也只有这两种）。所以让它"听见"的方式是**把音轨转成文字**：

- **字幕优先**：有 B 站登录态时用 `ai-zh` 字幕，瞬时且零成本。
- **ASR 兜底**：字幕拿不到时，用本地 `faster-whisper-large-v3` 听音轨转写。
  覆盖三类缺口：没登录、这条没字幕（纯音乐/冷门/外语）、字幕省略语气词。
- **两者互斥**：有字幕就不再转写，避免同一段话给模型两遍。

实现要点：

| 环节 | 做法 | 理由 |
| --- | --- | --- |
| 音频来源 | dash 独立音轨（`fnval=16`），取**最低码率**（~64kbps） | 转写只需听清说什么；高码率只让下载更慢，不会更准。实测 30 秒不到 1MB |
| 模型 | 复用本机 `FasterWhisperGUI/models/faster-whisper-large-v3`（3.1GB） | 免下载。中文实测一字不差；`base` 会把「红色的雨伞」听成「纳法红色的鱼闪」 |
| 进程 | `scripts/asr-server.py` 常驻，stdin/stdout 逐行传 JSON | 实测加载 ~8.5 秒、识别 12 秒音频 ~10.7 秒（**固定开销占大头**），每次重开等于白付 8 秒 |
| 就绪判定 | 服务端 stderr 打 `READY {...}`，Node 侧据此确认 | 不靠猜时间；模型真加载完才算可用 |
| 窗口 | 至少 12 秒（`max(12, 观看秒数)`） | 6 秒片段也要 10 秒识别，多给几秒几乎不增加耗时，却可能多听到一句话 |
| 失败降级 | 提示词写明「没能获取声音内容：<原因>，请只根据画面判断，不要臆测台词」 | 明确"没听到"比让模型猜更可靠 |
| 预热 | 启动 20 秒后后台加载，失败不影响任何功能 | 避免第一次刷视频时多等 8 秒 |

B 站插件卡的**声音内容**区块会显示：字幕可用性（取决于登录态）、
ASR 状态/模型/线程/加载耗时、失败原因与重试倒计时，以及一句话结论。

## 语音合成：能发语音（可插拔）

用 GPT-SoVITS + 达妮娅音色，让机器人**会发语音**。这是一个**完全可插拔的插件**：
不启用时这套东西在桥接里不存在。

两条触发路径：

1. **模型主动发**（`qq_send_voice`）——群友说「发个语音」「说句听听」时，模型自己组织
   一句话念出来。这是主要路径。
2. **桥接按概率替换**——5% 概率把普通文字回复换成语音，让日常聊天偶尔有声音。

> **血泪教训（2026-10-22）**：第一版只做了路径 2，没给模型工具、也没写进提示词，
> 结果群友说「发个语音」时机器人答「语音我发不出来呀」——它说的是实话。
> **能力不注册工具、不写进提示词，就等于不存在。**

- **默认关闭**：`socialV2.tts.enabled` 不为 `true` 就不加载——不探测模型、不起进程、
  不占显存。缺模型/缺底模只记一行日志，其余功能毫发无损。
  TTS 不可用时 `qq_send_voice` **根本不注册**，模型看不到、也就不会乱承诺。
- **失败不吞消息**：合成或发送失败自动回退成文字。
- **不碰外部仓库**：GPT-SoVITS 是独立目录，配置走环境变量，不改它的 `tts_infer.yaml`。

部署（已就绪的环境可跳过）：

```bash
node scripts/setup-tts.mjs --check    # 只检查缺什么
node scripts/setup-tts.mjs            # 自动克隆/下载/装依赖
```

启用：

```jsonc
"socialV2": {
  "tts": {
    "enabled": true,
    "dir": "C:\\GPT-SoVITS",
    "probability": 0.05,   // 5% 的单条回复改语音
    "maxPerHour": 3,       // 每小时最多 3 条
    "maxChars": 140        // 超过就发文字
  }
}
```

关键实现点：

| 环节 | 做法 | 理由 |
| --- | --- | --- |
| 音色 | ModelScope `villia/dania` 成品权重（v2ProPlus） | 免训练。GPT 155MB + SoVITS 173MB |
| 参考音频 | 必须与 `prompt_text` **逐字成对** | 写错会让合成语调与参考音频对不上 |
| 进程 | `scripts/sovits-server.py` 常驻 | 加载 24.8s（含预热），但之后 4 字 1.5s、42 字 2.9s；每句重开等于白付 25s |
| 概率 | 桥接掷骰，模型不参与 | 与自动 @ 同理：让机器控频率，避免模型忽多忽少 |
| 适用范围 | 只对**单条**文本回复；多段/含链接/过长不发 | 语音念链接没用，分条语音会刷屏 |
| 缓存 | 按文本指纹存 `state/tts-cache/` | 同句不重复推理 |

语音合成插件卡显示状态（未启用 / 不可用+原因 / 可用）、音色、引擎目录、
设备与加载耗时、触发概率，并有**试听按钮**（`POST /api/socialV2/tts-say` 返回 wav）。

## 自拍与形象图

群友问「发张自拍」「你长什么样」「看看你」「你是什么形象」时，模型调 `qq_get_self_image`：
**这张形象图会同时进入它的视觉上下文、并直接发到当前会话**（`assets/deepseek娘.png`，456KB，走 base64 内联）。

- **看图与发送合成一个动作**，不让模型分两步。分两步会出两种坏结果：看了图却忘了发；或者被要自拍时只对着图描述一遍长相——图在它手里，群里却看不到。
- **默认 `publish=true`**。只有「模型自己核对外貌但对方没要图」这一种情况才传 `false`。
- **发图不绕过既有管控**：reserved2 模式、总暂停、静默模式照旧生效；失败时返回 `sendError`，MCP 会明确告诉模型「图**没发出去**」，不让它假装发了。
- **不许凭想象描述长相**：形象图是唯一依据；也不提「人设」「系统给我配的」这类说法。
- 发完会写入会话时间线（`[图片] 发了张自己的形象图`），下一轮它自己知道刚发过，不会反复刷同一张。
- 触发范围**只限被问到自拍/长相**（用户选定），不会在自我介绍或日常聊天里主动甩图。

## B 站：自己刷视频与观看记忆

| 能力 | 说明 |
| --- | --- |
| 自己刷 | 潜水时随机（5~10 分钟）挑一条热门视频看；**先浅看 6 秒判断，喜欢再追加到 120 秒**；**帧率按 1 秒 1 帧取样**（120 秒 → 120 帧，自动切成 4 张拼图）；每天 ≤2 小时（按实际观看秒数） |
| 分区偏好 | **偏向二次元 / 游戏 / 科技 / 社会热点**（权重 6/5/4/3.5，生活与搞笑为中性 1）。加权随机而非白名单：偏好品类缺席时会自然落到别的分区，像人"主要看这些，也会随手点别的" |
| 游戏偏好 | **群友常玩的七款优先**：鸣潮 / 明日方舟 / 明日方舟：终末地 / 原神 / 崩坏：星穹铁道 / 绝区零 / 英雄联盟（含简称与英文名）。识别标题/简介/标签，命中给 **20 倍**权重——实测候选池里这类内容只占约 3%，不加成几乎刷不到；20 倍下约占 **55%**（10 倍时 36%） |
| 主动搜索 | 不只是刷热门榜：按「群友常玩的游戏 → 记忆里喜欢过的标签 → 分区」生成关键词并搜索，每次随机挑一个（实测会轮换「明日方舟：终末地」→「明日方舟」→「崩坏：星穹铁道」）。搜索结果与热门榜合并去重后一起挑 |
| 账号凭据 | 可选。放 `state/bili-auth.json`（已在 .gitignore），只需 `SESSDATA` + `buvid3`。**不配也能用搜索**——B 站搜索的 `-412` 只是"请求里没 Cookie"，匿名设备号即可；配了则走登录态拿个性化结果，**并且解锁字幕**（见下） |
| 字幕（声音变文字） | 用登录态调 `/x/player/v2` 拿 B 站自动字幕（`ai-zh`），**只取实际看过的那段时间**拼进提示词，并随记忆存 1200 字。实测热门榜 12 条里 11 条有字幕——画面只能看出场景，字幕直接给出"在讲什么" |
| 语音识别兜底（听觉） | 字幕拿不到时（没登录 / 这条没字幕 / 纯音乐 / 外语），用**本地 faster-whisper large-v3** 直接听音轨转成文字。复用本机现成模型（`FasterWhisperGUI`），常驻进程避免重复加载。音频走 dash 独立音轨、取最低码率。**与字幕互斥**：有字幕就不转写。详见下方说明 |
| 推荐分享 | 刷到喜欢的（兴趣分 ≥65）时，按 30% 概率、间隔 ≥6 小时在群里发：**一句推荐语 + 标题 + 链接**。链接由桥接按 bvid 拼（不让模型写，避免编错 URL）。**只推荐给活跃群**：近 24h 发言 ≥1 条的群才够格，候选内按活跃度加权（见下） |
| 现场搜索推荐 | 群友说「推荐点视频」时，模型调 `qq_bili_search` **实时搜新的**（不是翻记忆里的旧视频），并**原样带上标题和真实链接**；已看过的会被过滤，全看过时提示换关键词 |
| 选片加权 | 四个信号相乘后**加权随机**（不是取最高分）：分区权重 × 口味标签加成（≤2×）× 七款游戏加成（20×）× **喜欢的 UP 主加成（≤1.5×，喜欢过 ≥2 次才算）** |
| 群友发链接 | 主动调 `qq_watch_bili` 真看画面（支持 BV 号 / 完整链接 / `b23.tv` 短链），不占自己刷的额度 |
| 观看记忆 | **跨群全局共用**（`state/bili-memory.json`）：标题/UP主/分区/**简介**/**B站标签**/**字幕片段**/喜欢程度/兴趣分/备注，按 bvid 去重 |
| 口味归纳 | `qq_bili_memory` 可查历史、按标题/UP主/标签搜索；`taste` 只统计"喜欢"的，给出高频标签与分区 |
| 主动分享 | 刷到特别喜欢的（兴趣分 ≥65）时，按 30% 概率、间隔 ≥6 小时在群里提一句 |
| 控制台可见 | B 站插件卡：此刻在刷什么（阶段/标题/UP主/群）、今日额度条、口味归纳、最近看过、**「现在刷一条」按钮**（等刷完再报结果）、**「暂停 / 恢复自主刷」按钮** |
| 暂停自主刷 | 控制台一键停掉「它自己想看视频」，**写进 config.json 所以重启后仍保持暂停**。只停自动排期，群友发链接仍会观看；暂停期间点「现在刷一条」照常执行（那是手动指令，不是自主行为），返回里会标注「暂停中，本次为手动触发」 |

- 「多看/划走」用**帧数**实现：不喜欢看开头 6 秒 6 帧，喜欢看 120 秒 120 帧（1 秒 1 帧，自动分 4 张图）。真实按秒等待对模型没有意义
- **喜欢就真的多看**（修「感兴趣的视频也看的时间很少」）：原先是 12 秒 16 帧，占一条 6 分钟视频的 3%，等于只看了一眼。后来 30 秒 24 帧，实测能描述出「大厅 → 花盘特写 → 大厅全景 → 钩状物特写」这种多场景切换，而 12 秒时只能描述「同一机位的明暗微变」。
- **额度与观看深度再放宽 + 拼图去黑边**（2026-10-19 用户要求「总时长放宽到 2h，每次看视频尽量多看点」）：
  - 每日额度 30 分钟 → **2 小时**；喜欢档 30s/24帧 → **120s/36帧**；浅看 4s → 6s（略加长，减少"片头刚过就判完"）。
    代价很小——拼图仍 1568px、341KB，耗时 6.3s vs 5.4s。实测一条 45 分钟纪录片在 120s/36帧 下能看到主持人、平台界面、采访对象、拍摄现场等完整叙事线索。
  - **修拼图黑边**：原先格子强制按 1568×1568 正方形分配，横屏视频上下留大片黑（实测近一半画面是黑的，等于浪费模型有效像素）。现在用 ffprobe 探测源宽高比，按 `cols:rows × 视频宽高比` 分配画布——16:9 视频输出 1566×735 而不是 1566×1565，同样预算下每格实际像素更多。
- **主动搜索感兴趣的内容 + 推荐时带标题链接**（2026-10-19 用户要求「加上账号凭据，让它能自行搜索；推荐时顺便给出标题和链接」）：
  - **凭据**放 `state/bili-auth.json`（.gitignore 内），只需 `SESSDATA` + `buvid3`。实测发现 B 站 `search/type` 的 `-412 request was banned` **不是"没登录"，而是"完全没带 Cookie"**——带任意 `buvid3` 就正常返回 20 条。所以凭据是可选增强（登录态→个性化结果），不配也能搜。
  - **主动搜索**：关键词按「群友常玩的游戏 → 记忆里喜欢过的标签 → 分区映射」生成，每次随机挑一个。实测会轮换关键词（终末地 → 明日方舟 → 星穹铁道），搜索结果与热门榜合并去重后再挑。
- **推荐优先给活跃群**（2026-10-21 用户要求「更多推荐给活跃的群聊而不是非活跃的」）：
  - **旧实现正好相反**：`pickBiliSessionKey()` 取的是 `lastActionAt` **最久没动静的那个**
    （"最闲群"），而推荐复用了这个 key，于是推荐总落在没人说话的群里。
    实测 9 个群里有 2 个 24 小时零发言。
  - **活跃度定义**：近 N 小时（默认 24h）**群友**发言数，排除机器人自己。
    不能用 `lastActionAt`（只说明"最后一条何时"），也不能用 `recentMessages.length`
    （那是滚动窗口的 100 条上限，不是活跃度）——必须按时间过滤。
  - **两条规则**：① 硬门槛——近 24h 发言 ≥1 条的群才作为推荐目的地；
    ② 候选内**按活跃度加权随机**（权重 = min(上限, 发言数)），不是直接取最活跃，
    否则同一个群天天被推。实测分布：99 条的群 19.3%、69 条的 13.4%、
    只有 3 条的 0.6%，零发言的群 **0%**。
  - **落脚群与推荐目标分开**：刷视频只需要一个能承载画面的会话（冷群也行），
    但推荐必须发到活跃群。所以 `runBiliBrowse` 里选两次：
    `key = pickBiliSessionKey()`（落脚）、`shareKey = pickBiliSessionKey({ requireActive: true })`（推荐）。
  - 没有活跃群时**不推荐**，并在返回里说明原因（"最近 24 小时内没有群达到活跃门槛"）。
  - 控制台B 站插件卡显示各群活跃度与是否可推荐（当前 7/9 可用）。

  - **推荐分享**：原先 `share` 配置存在但**功能从未实现**（只在状态端点回显）。现在补上：兴趣分 ≥65 + 30% 概率 + 间隔 ≥6 小时，发「一句推荐语 + 标题 + 链接」。**链接由桥接按 bvid 拼**，不让模型自己写——模型编 URL 是高频问题（引用消息时就踩过"凭记忆猜编号"）。推荐语由模型写，失败则用中性兜底。
  - 凭据安全：只从 `state/` 读，日志和 API 返回值里**只报状态不打印内容**（测试里有断言守着）。
  - **踩坑：搜索结果没有 cid**。`search/type` 返回的 `cid` 恒为 0，直接拿去调 `playurl` 会 `-400 请求错误`（表现为"看视频失败"）。现在 `watchVideo` 在 cid 缺失时补一次 `fetchVideoInfo`——热门榜的结果是带 cid 的，只有搜索来的候选需要这步。
- **修「喜好的判断其实没在工作」**（2026-10-20 用户问「现在对于视频喜好判断逻辑是什么」后逐项实测）：
  - **口味标签原先基本没生效**：`pickCandidate` 只拿标签去比 `title + category`，实测热门榜 50 条只有 10 条命中，其中 **4 条是"只靠分区名"命中**（分区叫「音乐综合」就吃「音乐」标签）——那是把分区权重又算了一遍。现在匹配面是 `标题 + 简介 + UP主原生标签`，**不看分区**。
  - **泛词只在原生标签里认**：标题子串匹配会误伤——「莫斯科音乐厅恐袭」因为含「音乐厅」被判成"喜欢的音乐类"。音乐/MV/实况这类词改为只在 UP 主自己打的标签恰好叫这个时才认。
  - **游戏名从标签加成里剔除**：它们已经吃了 `gameBoost` 20 倍，再算一次是重复计分。
  - **新增 UP 主偏好**（`ownerBoost`，≤1.5×）：喜欢过 **≥2 次**的 UP 主出新视频才加分——只喜欢过 1 次可能只是那条视频火。实测这比标签更准（「他说电影」「ファル公」一出现就是真对味的那条）。
  - **搜索关键词不再被游戏名占满**：原先 7 个游戏名把 `max=6` 全部填满，记忆里的兴趣标签永远进不来，搜索退化成"只按游戏名搜"。现在游戏最多占 2/3，剩下的留给兴趣标签（实测变成 5 个游戏词 + 1 个「整活」）。
  - **兴趣分加绝对刻度**：实测 56 条"喜欢"里 interest 中位数只有 68、最高 82，全堆在 60~76，分数失去区分度。提示词现在给出锚点（30~45=没感觉 / 50~60=看完就忘 / 65~75=愿意看完 / 80+=会主动找同题材），并明确"大部分随手刷到的应该在 30~60，每条都给 70 就没意义了"。
  - **分享门槛 75 → 65**：≥75 的只占喜欢的 25%，再乘 30% 概率和 6 小时间隔，等于推荐几乎从不触发。65 覆盖约 70%，既能真的偶尔推荐，也不会推无聊的。
  - **实测一个副作用**：某次 5000 次选片里游戏占比是 **0%**——不是权重失效，而是热门榜那 9 条游戏视频**全在 7 天冷却期内**（当天刷得多），新鲜池里一条都没有。搜索补货（每次随机一个关键词）能补回 3~5 条新鲜游戏内容，选片时游戏占比回到 35%。所以冷却期和搜索补货是一对：**只有冷却期、没有搜索补货时，游戏内容会被刷干**。

- **控制台「暂停自主刷」按钮**（2026-10-20 用户要求）：
  - 语义是「只停它自己想看视频」，**不影响群友发链接时的观看**（那条路走 `/bili-watch`，只检查 `bili.enabled`）。
  - **复用 `selfBrowsing.enabled` 而不新开 `paused` 字段**：这个字段本来就是自主刷开关，`scheduleBiliBrowse` / `runBiliBrowse` 都已经在检查它。另开一个会变成两个真相源——配置里 `enabled:false` 而 `paused:false` 时到底算不算暂停？迟早对不上。
  - **必须落盘**：只改内存的话重启后又自己开始刷，用户会以为按钮没生效。实测验证过：暂停 → 重启 → 仍是暂停。
  - 暂停时**立刻清掉已排的定时器**，否则「暂停」之后它还会按原计划再刷一次。
  - **手动触发不拦**：那是你明确让它看一条，不是自主行为。但返回里带 `manualWhilePaused`，控制台提示「暂停中，本次为手动触发」，免得误以为暂停失效。
  - 按钮文案**跟着状态走**（暂停中显示「恢复自主刷」）——否则刷新后按钮还写「暂停」，点一下反而恢复了。
  - 实测效果：登录态搜索「鸣潮」返回官方战斗演示/过场动画（百万播放），匿名则混入抽卡规划、流水吐槽这类低质内容；「终末地」同样，登录态是官方 MV/EP/攻略，匿名有播放量仅 161 的视频。
- **1 秒 1 帧 + 拼图分页 + 字幕**（2026-10-19 用户要求「帧间隔缩短一些，最好一秒取样一次」「一定要把所有帧序列放在一张图上吗」「不能直接给模型视频和音频流吗」）：
  - **取样密度可配**：`framesPerSecond`（默认 1）决定"每秒抽几帧"，`maxFramesTotal`（120）封顶。以前帧数由 `framesLiked: 36` 写死，秒数一变就对不上；现在按 `秒数 × 密度` 算，120 秒自然得到 120 帧。
  - **分页拼图**（回答「一定要放一张图上吗」）：不用。120 帧挤进一张 1568px 的图，**每格只剩 142×80，字幕完全读不清**。现在按时间顺序切成若干张（每张 ≤`tilesPerSheet`=30 格），实测 120 帧 → 4 张，单格宽 261px（**约 1.8 倍**）。图注会写明"共 N 张、按时间先后排列"，模型按顺序连起来看。
  - **多图投递**：`deliverBiliPrompt` 和初判 `judgeBiliScan` 都改成把每一张作为独立 `image` part 投递（原先只发第一张，模型会把前 1/4 段当成整条视频）；`/api/socialV2/bili-watch` 返回 `images[]`，MCP `qq_watch_bili` 全部转发。
  - **为什么不能直接给视频/音频流**：DSH 的 prompt 协议只接受 `text` / `image` 两种内容块（`dsh-host-apiproxy` 的 `promptContentPartSchema` 是 text|image 的 discriminated union），本地网关 42 个模型也只声明了 `supports_images`，没有 audio/video 输入位。**但声音可以变成文字**：B 站给绝大多数视频配了 AI 字幕，用登录态调 `/x/player/v2` 就能拿到。
  - **字幕接入**：`fetchSubtitles()` 取字幕轨（优先人工 `zh-Hans` > `ai-zh`），`subtitleSnippet()` **只截观看窗口内**的行（多给会让模型以为"视频后面讲了 X"），拼进提示词并存入记忆。实测热门榜 12 条里 **11 条有 `ai-zh`**，内容质量足够判断"这视频在讲什么"。
  - **踩坑：字幕接口必须登录**。不登录时 `/x/player/v2` 的 `code` 仍是 **0**，只是 `subtitles` 是空数组——从返回值上根本分不清"没登录"和"这视频没字幕"。所以 `fetchSubtitles` 显式返回 `reason: 'noAuth'`，桥接启动时用 `setBiliCookie()` 注入登录态。
  - **补「群友要推荐时只会翻旧视频」**（同日反馈）：原来只有 `qq_bili_memory`（查**已有**记忆），没有搜索工具——群友问「推荐点视频」时模型只能翻旧的，还临时编了两条没链接的。现在加 `qq_bili_search`：实时搜、**过滤已看过的**、返回标题+真实链接；preset 里明确要求"必须现场搜，不要翻旧账""不要自己拼或凭印象编 bvid/链接"，全看过（`allSeen`）时换关键词。
  - **补「读不到简介，问他相关信息答不出来」**（同日反馈：群里追问"啥视频啊"，它只能答"那种动漫解说"）。查出三层原因并都修了：
    ① **简介根本没进提示词**（`videoFramesHint` 原来只有标题/UP主/分区），且两个 prompt 里截断到 120 字 → 现在统一给到 600 字。
    ② **简介为空时没有兜底**：实测热门榜 10 条里有 **3 条简介 0 字、2 条只有一个 `-`**。现在简介过短（<12 字）时多打一次 `/x/tag/archive/tags` 拿 UP 主填的标签——实测一条简介为 `-` 的视频拿到了「搞笑/AI/搬运/deepseek/吃饭/大肥鱼」，足以判断内容类型；分P标题也一起给。
    ③ **模型会瞎编 bvid**：实测日志里缓存的是 `BV14cnn6REvX`、它记录时传的是 `BV1qh411c7mR`（完全编造），于是缓存查不到、记忆里存成两条不同视频、简介也丢了。现在 `qq_bili_record` 的 `bvid` 改为**可选**，桥接自动用"刚看完的那条"，不符时打日志纠正。
    简介与 B 站原生标签都写进记忆（`desc` / `biliTags`），事后追问可直接查到。
- **两段式观看**（修「为什么总是 8s11 帧」）：原实现**先定看多深、再去看**，而"喜不喜欢"要看完才知道，于是永远走 `liked=null` 的中庸分支，喜欢/不喜欢的帧数配置从未生效。现在改成：浅看 4s/6 帧 → 让模型只回一行 JSON 判断 → **liked=true 才追加**到 30s/24 帧（时间窗口变长，不是另截一段）。实测同一 UP 主的两首 K/DA 会被判成一喜欢一不喜欢，说明模型真的在看画面
- **修「刷到黑屏」**：MV/PV 常有 2~5 秒黑场淡入，浅看 4 秒正好整段落在黑场里（实测 K/DA 官方 MV 拼图平均亮度仅 5.0，正常画面 31~78）。现在抽帧会测亮度，太暗就自动把采样窗口往后挪（最多 2 次）；同时初判提示词要求"暗不等于黑屏"，尽量从字幕/标题/分区推断内容
- 偏好权重可在 `socialV2.bili.selfBrowsing.categoryWeights` 调整；全设 1 就退化成纯随机
- 记忆里的高频标签会给对应内容额外加权（上限 2 倍），让"我喜欢什么"自我强化但不会垄断
- 只挑最空闲的群落脚；有未读/繁忙/正在活跃的群会跳过，不打扰正在聊天的人
- 记忆写入做了 mtime 比对：桥接与 MCP 是两个进程，各持一份内存副本时会互相覆盖（实测丢过数据）

## 联网

- 可插拔搜索引擎注册表（`src/web-search/engines/`）：往目录丢一个 `.mjs` 即成新引擎，配置决定顺序与回退
- 内置 weather / baidu / bing-html / bing-rss / duckduckgo；引擎抛错进 5 分钟断路器，代理引擎未配代理时跳过
- **天气查询直接出数据**：`weather` 引擎调用 Open-Meteo（免 key），返回当前温度/体感/湿度/降水和未来几天预报；不再依赖搜索摘要里有没有温度
- **多词查询抗降级**：必应对「标题 + 关键词」这类查询会只匹配首个词（返回「魔法」词条而不是《魔法少女的魔女审判》）。引擎会识别"结果与查询毫无字面交集"，改用**最长实义词块**重试一次（时间/天气/疑问词不参与，`南京 今天 明天 天气预报` → `南京天气`），并告诉模型本次结果实际来自哪个检索词；重试仍无关就返回空、让引擎链继续试下一个，而不是把无关条目当答案
- `web_fetch` 只读抓取，带 SSRF 防护（拒绝内网/环回/DNS rebinding，重定向逐跳校验）；自动识别 UTF-8/GBK/GB2312，403/404/Cloudflare 验证页会明确报错，境外站点直连失败时自动走代理重试
- 兼容 Clash fake-IP：系统 DNS 本身在 `198.18/19` 段时，`198.18.0.0/15` 不再当内网拦截（正常网络仍拦截），避免所有域名被误判成"解析到内网"
- `web_view_image` 按图片 URL 取图给模型看（单张 ≤2.5MB，一次 ≤3 张）

## 仿真调度（reserved2）

- **唤醒优先级**：私聊 > @ > 提问 > 指定成员 > 名字 > 关键词 > 任意消息 > 回复检查 > 超时 > 主动检查 > 启动补投。新建高优先级合并窗口最多 1.5s（普通默认 8s）；已排好的窗口升级原因时不重设计时器
- **补发按优先级**而非 FIFO——繁忙期间积压的唤醒不会让 @ 被更早的拍一拍插队
- 潜水前强制观察窗口（先确认没人等你），但**只会被"还没答过的 @"拦下**，已回过的旧消息不构成理由
- 沉睡前可设唤醒条件（@/名字/关键词/提问/拍一拍/概率/指定成员），多档下限上限防永眠
- 分条发送：`qq_send_message` 数组，或 `qq_send_burst` 带间隔模拟真人打字

## 群内互动

- **贴表情**：`qq_react_message` 由模型自主决定贴不贴（桥接只校验 + 限流）
- 表情包体系：收藏、备注、按语境挑选、向 QQ 回源同步
- **表情包本地缓存标注**：同步时为每个收藏表情生成 `state/sticker-cache/<md5>.json`（QQ 备注、URL、使用次数、本地笔记、标签、用法、自定义 extra），看图时同时缓存图片；控制台 07「表情与上下文」可开关 `读取本地缓存信息`，开启后 `qq_list_stickers` / 唤醒摘要会读取这些更详细的本地标注
- 动图抽帧拼图：默认最多取 20 帧拼成静态图，数量与开关可配置，帮助模型理解动画变化
- 黑话/网络用语学习：从群聊提取候选、联网研究释义，经管理员确认的词条才会注入聊天提示词
- 记忆与印象：按会话保存轻量长期记忆与群友印象，可查询和移除；不提供定时提醒，也不会删除 QQ 聊天记录
- **跨会话人物记忆**：同一个 QQ 号在多个群/私聊里会认出是同一个人，复用「喜欢/讨厌/在玩/职业」等稳定偏好；
  只共享结构化偏好，不共享聊天原文、情节摘要、群名或群内事件。默认开启，控制台 19 卡可关、可查看、可按人忘记或整体清空。
- **记忆断层提醒**：程序关闭/重启超过阈值后，下一次唤醒会给模型补一句「这个会话中间断过」的背景，
  提醒它先查历史记录、不要凭印象接旧话题；首次启动和正常连续对话不提示。默认关闭，控制台 19 卡可配阈值。
- 点单判定：群友点单时桥接掷骰决定「照做 / 自由发挥」，避免有求必应或总是装傻

## Token 熔断（二期，默认关闭）

- 每个群/私聊按**自然日（上海时区）**累计「总输入（含缓存）」，超过 `warnTokens` 私聊管理员提醒一次，
  超过 `fuseTokens`（或 `fuseUncachedTokens` 第二阈值）进入熔断。
- 熔断后**只停该会话的自动唤醒与 B 站自主刷**；管理员私聊、控制台手动唤醒/手动刷不受影响；
  群里不会收到任何提示（报错不进群）。
- 计数来自 `assistant/message` 的 usage，只统计最终汇总、不重复统计流式 chunk；每 5 分钟随上下文扫描落盘，
  重启保留当天状态，日切自动归零。
- 控制台 14 卡「会话级 Token 熔断」面板可开关、设**全局默认阈值**（只影响未自定义的会话）、
  **给每个会话单独设阈值**（逐行保存，不被全局保存覆盖）、查看各会话计数并解除；会话列显示群名/QQ 昵称。
  管理员私聊也可发 `/tf` 查看、`/tf off group:群号` 解除。
- 默认关闭；关闭时不计数、不读状态、不改变任何唤醒行为。实现见 `src/token-fuse.js`。

## X（推特）按需查询

- 群友指定账号、条数或日期后，由 `qq_fetch_x_posts` 按需拉取并发帖文卡片；当前没有定时轮询和自动推送

## 安全与准入

- **私聊准入三态**：`allow.privateMode` 支持 `friends`（好友自动放行，非好友临时会话走白名单）/ `all`（纯黑名单）/ `list`（默认，白名单）；聊天模式中 deny 优先
- **报错通知只私聊管理员**：`notifyOwnerOfError` 汇总需要通知的错误，底层异常也可能只写日志；带自检端点，通知可配置开关与节流
- **敏感信息脱敏**：路径/令牌/密钥特征检测，命中的回复会被拦截并通知管理员
- 聊天 preset 的工具白名单（`SAFE_PREFIXES`）限制 shell/文件等工具；`closed-agent` 是管理员私聊专用的完整工具模式
- 二代发送工具检查当前模式的准入策略及会话令牌，发送还受暂停、静默和频率限制；好友准入不等于所有旧版 MCP 发送工具都放宽白名单

## 运维

- **DSH 配置自愈**：provider 丢失（打开 DSH 桌面端会把 `settings.yaml` 改名成 `.imported`）自动修复并通知
- 本地 Web 控制台 `127.0.0.1:3100`：管理模式、人格、准入名单、静默、活动日志与令牌。控制台接口支持即时更新；手工改文件的生效方式见「运行与运维」
- **人格按群配置**：控制台 05 可设置全局默认人格，并给每个群单独选择角色（`state/conversation-roles.json`）；未单独配置的群跟随默认。群里 `/role <角色名>` 只改当前群，`/role off` 回退默认。角色卡只显示机器人当前所在群；已离群会话不混进来。
- **魔鱼人格卡**：偏上下文造梗的群聊损友，擅长原词回敬、谐音双关、故意歪解、复读变奏和 callback；内置群文化自适应与认真求助时收嘴的边界，可直接在控制台 05 或 `/role 魔鱼` 启用。
- **白名单显示名称**：控制台 10 的群号后面显示群名，私聊/管理员 QQ 后面显示昵称（非好友会实时查一次资料）；查不到的群会标注「未在当前群列表」。
- **失效会话清理**：控制台 19「上下文与记忆」把会话分成「当前群聊会话 / 已不在当前群列表的群聊会话 / 私聊会话」；已离群群聊提供「删除会话」按钮，会清理本地会话映射、消息日志、情节/长期记忆和人格覆盖（当前仍在群的会话禁止删除）。
- 会话清理：`scripts/prune-dsh-sessions.mjs` 清理调试残留会话

## 控制台界面（摘要卡 + 整页详情，2026-10-22）

- **首页是一屏摘要卡**（当前 24 张），每张固定 136px 高、尺寸一致。
  **默认只显示序号和卡片名称**（在卡片正中间）；鼠标移上去或键盘聚焦时，
  名称整体上移、下方浮现 1~2 行功能简介（当前模式、待裁决数、今日 Token…）。
  有待办（挂起审批 / 加好友）的卡片右上角有呼吸圆点。
- **点卡片展开整页详情**：不弹小窗。卡片位置先出现一块同尺寸的白色"面"，用 `transform`
  长到详情页里**大白卡的实际矩形**（不是视口），页面背景和边距从一开始就在；内容随后淡入。
  左上角「← 返回」或 `Esc` 返回，返回时整页背景淡出、大白卡缩回原摘要卡，并还原焦点。
  `prefers-reduced-motion` 下直接切换。
- **实现方式**：详情 DOM 原样保留，点开时把**同一个节点**移进整页，返回移回——不是重建，
  所以既有的 `getElementById`、事件绑定与 3 秒轮询零改动（详情页打开期间数据照常刷新）。
  摘要网格只加 `inert`、不隐藏：卡片位置与页面滚动位置都保留，返回动画才有落点。
- **背景**：一块缓慢飘动的「布料」——竖线按采样点做横向位移，几组低频正弦沿高度叠出折痕，
  相邻竖线的相位差让布面堆出明暗带；鼠标经过时附近的点被"拨"开，靠弹簧与阻尼回弹、
  并沿线传播（仿 SnowLuma 登录页的质感）。`prefers-reduced-motion` 下只画静态折痕。
- **视觉**：oklch 色板 + 液态玻璃（摘要卡 12px、黑话/凭据浮层 20px 背景模糊）+ 跟随鼠标的卡片柔光。
- 顶部目录已移除（一屏即可看完，无需跳转）。
