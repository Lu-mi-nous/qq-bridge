# 版本号迭代标准

> 生效日期：2026-10-27。此前版本号是「想到才改」，曾出现三类乱象：
> ① 8 处版本号手动逐个改、漏改；② 更新日志一直堆在「未发布」，发布 0.4.0 时没有剪版；
> ③ package.json 已经是 0.4.1、日志却还没有 0.4.1 段。本文件把这三件事都固化下来，
> 并有 `scripts/test-version-sync.mjs` 做护栏——不照做测试会直接失败。

---

## 1. 版本格式与取号规则

`MAJOR.MINOR.PATCH`（SemVer），**0.x 阶段 MAJOR 固定为 0**：

| 升哪位 | 什么时候 | 例子 |
| --- | --- | --- |
| **PATCH**（0.4.1 → 0.4.2） | bug 修复、文档、测试、不影响对外行为的内部小步重构 | 修「@ 不回」、控制台排版修正 |
| **MINOR**（0.4.x → 0.5.0） | 新功能、新 MCP 工具 / 新控制台能力、对外行为变化、破坏性变更（0.x 阶段破坏性变更走 MINOR）、一个大阶段重构完成 | R4.5 插件化一批完成、新增内容审查 |
| **MAJOR**（→ 1.0.0） | 0.x 期间**不用**；等对外接口稳定、愿意承诺兼容性时才升 | — |

- 版本号只向前，不回退；同一版本号不剪两次。
- 当前版本永远是 `package.json` 里的值，`GET /api/about` 动态读取它。
- `plugins/qq-mode-console` 跟随主包版本（0.x 阶段不独立发版）；
  插件 manifest 里的 `engines.qqBridge` 是**最低要求**，不随剪版改。

## 2. 版本号写在哪：1 个事实源 + 7 处镜像

**`package.json` 是唯一事实源**。其余全部是镜像，只允许通过脚本改：

```bash
npm run version:set -- 0.4.2
```

镜像清单（新增镜像位置时，在 `tools/set-version.mjs` 的 `MIRRORS` 里加一行）：

| 位置 | 处数 |
| --- | --- |
| `package-lock.json` | 2（根 + packages.""） |
| `public/console.html` | 3（侧栏 / 关于徽标 / JS 兜底） |
| `src/mcp-snowluma-safe.js` / `mcp-host-server.js` / `mcp-web-search-safe.js` | 各 1 |
| `plugins/qq-mode-console/package.json` | 1 |

**不要手改任何一处镜像**——`test-version-sync` 会比对全部镜像，漏改/多改都算失败。

## 3. 什么时候改版本号：剪版时，不在开发中途

开发期间 `package.json` 保持**上一个已剪版本**；所有新条目进更新日志的「未发布」段。
版本号 + 更新日志必须**同时**动，不允许出现「版本号已升、日志没剪」或反向。

**剪版流程（release checklist，全部满足才算剪完）：**

1. 全量测试通过：0 个真实失败（环境类失败除外）；
2. 更新日志「未发布」段的条目齐全、措辞是技术性的（不发"用户要求"腔）；
3. `npm run version:set -- x.y.z` 同步全部镜像；
4. README 更新日志：`### 未发布` 改名为 `### x.y.z（YYYY-MM-DD）`，顶部新建空的
   `### 未发布`（段内留一行指引，格式见现有文件）；
5. 同步发布副本（标准动作 + 脱敏四类对象）；发布副本的 `docs/CHANGELOG.md`
   从主仓 README 的已剪版本段同步（标题层级 `###` 提为 `##`，按版本倒序）；
6. 剪版后该版本内容冻结，后续改动进新「未发布」。

剪版的**频率**没有硬性规定，触发条件满足其一即可：一组功能/修复收尾、
全量测试绿了想留个存档点、发布副本要更新。

---

## 4. 更新日志规则（README「## 更新日志」）

- 结构固定三段式，**最新在最上**：

  ```
  ### 未发布            ← 开发中的条目堆这里（空段也保留，段内有一行指引）
  ### 0.4.1（2026-10-27）
  ### 0.4.0 及更早（…）
  ```

- 条目格式：`- **标题**（日期，可带"用户反馈/要求"）：做了什么 + 为什么`；
  修 bug 优先写清真因。
- **不再开「未发布（续）」**——段太长就说明该剪版了，而不是续一段。
- 控制台「开发日志」弹窗（`/api/dev-log`）按 `###` 分组读取本章节，
  段名就是用户看到的分组名，所以剪版不只影响观感。

---

## 5. 护栏与工具

| 工具 | 作用 |
| --- | --- |
| `npm run version:set -- x.y.z` | 一次性同步全部镜像；漏镜像会报 MISS |
| `scripts/test-version-sync.mjs` | 护栏：镜像一致 + 日志结构（唯一未发布桶、无"（续）"、当前版本已剪版） |
| `GET /api/about` | 控制台显示的版本，来自 package.json，无需单独改 |

> 历史注记：0.4.1 是「先改版本号、后补剪版」的一次性操作（2026-10-27 用户要求），
> 本标准生效后不再允许这种顺序。
