# 功能对比：当前工作副本 vs 原版

> 配图：[`docs/feature-comparison.png`](feature-comparison.png)

**基线说明**：基线取自上上游 `main` 分支的发布包（MIT），与 DSH 0.1.2-alpha.1 协议适配分支血缘不同。

## 规模变化

| 指标 | 原版 | 当前 |
| --- | --- | --- |
| 源码总行数 | 11,078 | 20,900 |
| 源码模块数 | 13 | 38 |
| MCP 工具数 | 41 | 50 |
| 控制台 API 端点 | 77 | 89 |
| 配置项总数 | 168 | 253 |
| 测试脚本数 | 13 | 57 |

统计均排除 `.bak` 备份文件。核心文件 `src/bridge.js` 从 8,078 行增至 10,794 行。

## 全新能力（原版没有）

**消息与媒体**
- 引用消息中的图片：原版只取 `sender + text`，图片段被丢弃，模型看到的是 `[引用 某人：[图片]]` 却取不到图；现在解析引用文案并回源取图
- 主动发图片：图片落盘后直发（图片独占一个气泡，不混文字）
- 主动发视频：超过 100MB 自动跳过

**群内互动**
- `qq_react_message` 贴表情（模型自主决定贴不贴，桥接只做校验和限流）
- 动图抽帧拼图：等间隔取 20 帧拼成一张静态图
- 元标记过滤：剥离模型自造的 `[[...]]` 内容

**图像能力**（整块为新增，原版只有收藏表情包）
- 三源图库检索：safebooru / pixiv / yande.re
- 按需查图与日榜（单次限 4 张）
- 画风打分与质量门（CLIP 提取画风分）
- 差评自动换图：收到「不好看」自动删图重发
- 收藏原图：回源取原图存档，而非库内压缩版
- 反向搜图：SauceNAO，带站名/画师清洗
- 限定图源：强制来源，模型没填时桥接自己识别
- 代理隧道绕行：CONNECT 隧道绕 DNS 污染取图
- 超分放大（群友可主动要）：说「帮我超分/放大一下/来个高清的」即触发；Real-ESRGAN（复用本机 Upscayl）；未安装时菜单与工具都不出现、自动回退 lanczos
- 超分结果回传：默认发回会话，大图不压缩（一次性回环 HTTP 托管，绕开 OneBot 的 2MB 请求体上限）
- 超分磁盘缓存：按 `原图哈希 + 模型 + 目标宽度` 缓存，双阈值清理（3 天 / 500MB）

**X（推特）帖子监控**（整块新增）
- 登录态翻历史 + 置顶帖子识别
- ffmpeg 渲染帖子卡片（字体回退链、两行头部布局）
- 媒体与视频：图片不裁切，视频 ≤ 100MB
- 译文渲染 + 媒体 TTL 缓存

**运维与自愈**
- DSH 配置自愈：provider 丢失自动修复（桌面端打开会把 `settings.yaml` 改名成 `.imported`，导致 `no adapter`）
- 会话清理脚本 `prune-dsh-sessions.mjs`
- 桌面模型切换选单（保住看图能力）

## 在原版基础上增强

| 项目 | 原版 | 当前 |
| --- | --- | --- |
| 回复/引用 | 引用人 + 原文 | 符号引用 `latest` + `[引用]` 审计日志 |
| 联网搜索 | 硬编码 Bing 抓取 | 可插拔引擎注册表 + 回退链（4 个引擎） |
| 私聊准入 | 白名单 + 黑名单 | 三态策略（好友自动放行） |
| 敏感信息脱敏 | 单行正则 | 多模式（路径 / 令牌 / 密钥） |
| 报错信息去向 | 可能发进群 | 只私聊管理员 + 自检端点 |
| 唤醒优先级 | 10 档 | 11 档 + 高优先级批窗口缩至 1.5 秒 |
| 补发选择 | FIFO（最旧优先） | 按优先级挑选 |
| 测试套件 | 13 个脚本 | 57 个脚本 / 426 项断言 |

**联网搜索**额外补了失败隔离：引擎抛错进 5 分钟断路器，代理引擎未配代理时直接跳过（不熔断）。

## 保留未变

群 / 私聊消息接入链路、表情包收藏与备注、工具白名单（preset 限制）、人格热重载、SIM 调度骨架。

## 两个值得说明的点

- **唤醒优先级表原版就有**，我原以为是新增的；实际改的是*补发选择*——原版 FIFO 取最旧的一条，导致用户 `@` 之后被更早的 `poke` 插队，延迟 90 秒才回复。现在按优先级挑，同优先级取最新。
- **引用消息中的图片**是原版的真实缺陷，不是缺功能：`resolveReplyInfo` 明确丢掉了媒体段。
